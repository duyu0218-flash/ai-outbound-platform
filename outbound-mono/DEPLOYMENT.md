# 单实例部署与升级

> **本系统事务串行化依赖 JVM 内锁，仅支持单实例部署。需要使用多实例时，必须先把 PlatformLock 替换为分布式实现并重做并发验证。**

API、AI、语音控制、录音、实时媒体同一 jar/JVM。不要启动第二应用实例，包括滚动升级或热备进程；没有 Redis 单实例哨兵自动阻止错误部署。FreeSWITCH、MySQL、Redis、对象存储可以作为基础设施运行，不是第二应用进程。

## 数据库前置条件

MySQL 8.4，InnoDB；配置文件或启动参数必须明确设置：

```ini
innodb_flush_log_at_trx_commit=1
sync_binlog=1
transaction-isolation=REPEATABLE-READ
```

应用启动用独立 voiceLedgerDataSource 实测上述全局参数/连接隔离级别，未满足拒绝启动。全局 RR 仍应配置，以保证维护工具的一致性。硬件/文件系统必须正确履行 fsync；应用参数不能补偿断电不持久的存储。

独立语音池使用 MYSQL_JDBC_URL / MYSQL_USER / MYSQL_PASSWORD，同库不同池，不加入业务事务。Flyway 先执行原 V1，再执行 V2；应用表 44 张加迁移元数据 1 张。允许单独配置 FLYWAY_JDBC_URL / FLYWAY_USER / FLYWAY_PASSWORD，指向同一目标库。业务凭证须能读写新增辅助表。上线前独立执行迁移并备份，禁止编辑已执行 V1。

模型配额启用开关映射：原来已配置持久路径的部署设置 `LLM_QUOTA_ENABLED=true`；原来未配置的保持 false（默认），仅保留原连接数限制。LLM_QUOTA_SCOPE/RPM/TPM/RPS 名称及默认值不变。

旧本地辅助账本属于开发数据，本次明确不导入；新库从空开始。不能据此把已投入生产的数据当开发数据清除。原业务数据的生产迁移/初始化需要部署方按实际环境完成，本轮未连接或修改生产。

## 配置与启动

填充 `.env.example`，由部署环境导出变量/注入密钥。不要将示例当生产配置。生产环境演示账号关闭、密钥与 CORS 满足原启动检查；主服务仅监听 SERVER_PORT，录音回调与媒体 WebSocket 指向该进程。真实语音还需 FreeSWITCH ESL、拨号路由、录音目录权限及上游凭证。

JDK 17 使用 `-XX:+UseG1GC -XX:MaxGCPauseMillis=20`，选择理由是保留锁定 JDK 的默认收集器并明确暂停目标；它不是实测音频保证。专属媒体线程池、全局有界队列、每连接帧上限、过载丢最旧帧、堆外 DirectByteBuffer 保留。媒体压测/真机验证是原阶段 6 验收项，尚未完成。目标 Linux、真实 PBX/音频/云模型的 500 总在途容量须另测。

## 升级流程（禁止滚动）

1. 备份 MySQL 与对象存储，记录旧 jar、配置版本和恢复点；暂停入口/任务调度。
2. 向旧应用发送正常停止信号，等待 graceful shutdown。
3. **确认旧 PID 已退出且服务端口不再由旧进程监听**；不能只根据发出了停止命令判断退出。
4. 在没有应用写入时执行/核验 Flyway 迁移，确认 44 应用表及迁移记录。保留旧 V1 校验和。
5. 启动唯一新 jar。检查日志中的 MySQL 参数验证、Flyway、GET /healthz 200，以及真实配置下的 /readyz。
6. 恢复入口/调度，验证登录、数据回显、mock 或已批准真实语音链路。回退同样先停止新进程并确认退出；不得两个版本重叠。数据库回退需按已备份恢复方案操作，不能直接删除 V2 或盲目回退 jar。

## 备份与恢复

持久业务备份统一为 **MySQL + 对象存储** 两项：MySQL 包括 34 业务、8 语音、2 模型配额表及 Flyway 历史；对象存储包括录音、元数据及删除墓碑。使用一致性 MySQL 备份（含 binlog 恢复点）与对应对象存储快照/版本；定期在隔离环境验证恢复后录音索引及对象相符。Redis 是原短期信号/队列设施，按原初始化/重建逻辑恢复，不作为第三份权威账本。

spool/源录音是待上传过程文件：升级前排空；无法排空时保存其工作目录及处理状态，防止上传中的文件被清理。密钥由独立密钥管理设施保管，不写入普通数据库备份说明或 Git。

## 未验证与正式上线前置条件

本轮仅本机开发验证。测试环境未发布、真机未验证、生产未发布。正式上线前须完成目标宿主 MySQL 参数、备份恢复演练、配置校验、真实 SIP/RTP 与云供应商、浏览器音频设备、媒体长稳/GC/丢帧及容量验收，再据原发布流程设 JAVA_RELEASE_ACCEPTED。不能用 /healthz 或 mock 测试替代这些验收。
