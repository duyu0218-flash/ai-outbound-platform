# S2S 完整短句内容审核与本地验收

2026-10-26。本次“内容安全”指色情、暴力、仇恨歧视、违法行为指导等模型输出风险；本记录更新此前 v2 文档中 S2S 输出审核的实现状态。GitHub 更新不等于发布或真实电话验收。

## 播放路径与边界

`S2S 实际输出 PCM → 有界缓存 → 独立流式 ASR 的 final 及时间边界 → 累计上下文语义审核 → 有界已审核队列 → 播放器`

- 不以 S2S 自带的文字、partial 或模型自称“安全”作为播放批准依据。独立 ASR 接收播放器原本将播放的那份 PCM，按实际采样时间映射句子边界。
- final 必须有有效、单调、未越界的起止时间。完整句末标点才能提前提交；未完成的尾句等模型成功结束、ASR 完成且尾部覆盖检查通过后再送审。
- 识别区间之间存在未识别有声内容时阻断；低能量间隙也会替换为静音。未审核的音频尾部不会发送。
- 使用阿里云 TextModerationPlus 的 `llm_response_moderation` 独立审核。只有 HTTP 200、业务 Code 200、RiskLevel=none、结果仅有 nonLabel 且包含 RequestId 才能放行。low/medium/high、空结果、协议错误、限流、超时、缺少配置均阻断；不自动重试。
- 每句送审包含当前回复累计的独立识别文字，及有界的已确认对话上下文，避免单句孤立审核。原有禁用词和业务承诺限制仍执行，但不替代语义审核。
- 审核与实际播放分别执行，上一句播放期间可识别和审核下一句。仍按句子顺序出声。取消会关闭识别、审核请求及其响应体，清空待播队列，已有媒体代际校验阻断迟到的旧音频。
- 任一失败会中止本次模型回复并关闭媒体，由原业务失败链路结束通话；不会改为直接播放，也不会让模型临时生成兜底内容。
- 正式通话和后台供应商音频对比均经过此闸门。对比音频审核失败时不提供该轮音频下载/试听。

本次未增加关闭审核的选项。历史 `reviewed`/`streaming` 数据可读取，S2S 保存时统一为 `sentence_review`；运行时所有模式均走相同强制审核。`direct_s2s_enabled` 只控制是否按用户语音端点发起生成，输出仍需审核；流程画布通话继续由业务控制。

## 降低等待的实现

识别连接建立与模型生成并行；实际音频到达后持续识别，完整句 final 到达即送审，不等整段回复。独立的审核和播放线程允许“生成后句、识别后句、审核后句、播放前句”重叠。没有人为添加固定的 1 秒播放等待。

默认边界：审核请求总期限 1200ms；未审核音频最多 6000ms，满额后背压并限时退出；原始回复总量最多 30 秒 PCM；识别输入队列最多 64 个 100ms 帧，final 队列 16 条，已审核待播队列 2 段；审核并发最多 64。外部额度仍需单独批准，默认并发值不是 QPS/容量证明。长句在边界内无法最终化会被阻断，不会为了低延迟截取未确认音频。

结构测试证明了“首句可早于整轮 DONE 播放”和“后句审核可与前句播放重叠”。这是本地并行机制证据，不能换算为真实账号增加 300ms 或电话 p95≤某值。真实时延、额外 ASR/审核费用与漏检率均待账号及电话实测。

## 平台配置

与百炼 API Key 分开，使用企业受控 RAM 子账号的内容审核凭据，仅授予需要的 TextModerationPlus 权限；支持 `_FILE`。密钥不写入租户快照、页面或审核事件。生产只接受受限的国内官方 HTTPS 接入点，禁止重定向；HTTP 环回地址仅供本地模拟测试。

```dotenv
VOICE_AI_SAFETY_ACCESS_KEY_ID=
VOICE_AI_SAFETY_ACCESS_KEY_SECRET=
VOICE_AI_SAFETY_ENDPOINT=https://green-cip.cn-shanghai.aliyuncs.com/
VOICE_AI_SAFETY_REGION=cn-shanghai
VOICE_AI_SAFETY_TIMEOUT_MS=1200
VOICE_AI_SAFETY_MAX_PENDING_MS=6000
VOICE_AI_SAFETY_MAX_CONCURRENT=64
VOICE_AI_SAFETY_POLICY_REVISION=sentence-v1
```

语音方案继续配置独立识别所需的 `VOICE_AI_REALTIME_SPEECH_PROFILE`（默认 aliyun-cascade）和 ASR 批准额度。每轮审核额外占用一份该供应商 ASR 额度；必须将它和客户侧识别一起计入容量及成本。实际拨号前检查审核配置，启动 S2S 引擎前再次检查。缺少审核配置不启动付费模型连接。

通话快照固定审核端点、期限、缓存上限及策略修订号；切换配置用于后续通话。凭据轮换应在排空旧通话后进行。事件只记录审批请求 ID、策略修订、待播音频/文字哈希、样本边界与审核耗时；“审核通过”不代表“实际已播”。媒体关闭事件也保留本轮审核证据。

接口与签名依据：[TextModerationPlus 返回协议](https://help.aliyun.com/en/document_detail/2671445.html)、[官方 RPC 签名接入说明](https://www.alibabacloud.com/help/zh/content-moderation/latest/access-guide)。真实账号权限、地域接受情况、服务规则覆盖与计费未验证。

## 测试与交付状态

命令：`mvn verify`、`mvn enforcer:enforce`，以及 `node tools/test-voice-measure.mjs`。新增 S2sContentSafetyTest 验证：

- 未批准前零输出；首句播放不等整轮结束；后句审核不等前句播完。
- 累计上下文发现第二句风险后阻断；部分识别、缺失/乱序/越界时间戳及未覆盖有声区不能批准。
- 不完整尾句等待成功结束，低能量未识别间隙静音，取消后迟到的审批不放行。
- 真实本地 HTTP RPC 签名正确；高/中/低风险、缺少结论、矛盾结果、缺少请求 ID、错误 JSON、429、超时及生产非法端点均阻断。
- NativeMedia 集成：模型文字声称正常、独立音频识别结果违规时，即使旧模式设置为 streaming，实际 PCM 输出仍为 0，并保留阻断证据。

全量 `mvn verify` 通过：285 项单元测试 + 320 项集成测试，共 605 项，失败/错误/跳过均为 0。末次补齐非法配置错误处理后，再执行 56 项语音单元测试及 VoiceAiHttpIT / FrontendBrowserIT，全部通过；主业务浏览器 35 组、语音页 9 组检查通过。Spotless、Mapper XML、前端格式、依赖 Enforcer、Jar 独立启动与测量工具合成自测通过。机器摘要见 `s2s-content-safety-validation.json`。日志和本地音频位于忽略目录 `verification/s2s-content-safety-20261026/`，不随 Git 提交。源代码已修改；静态检查通过；开发环境功能测试通过；测试环境未发布、真机未验证、生产环境未发布。

## 未验证项、已知限制及上线前置条件

- 未调用真实付费识别/审核接口，未拨打电话，未部署。供应商权限、时间戳精度、识别完整率、真实审核覆盖、漏检/误拦截和 p50/p95 未验证。
- 目前基于实际音频的独立转写做语义审核，没有独立的非语言声音分类器。ASR 与审核服务都可能漏检，不承诺“零违规”；非语言风险、低声/谐音/方言等对抗样本须单独评测。
- 识别缺少可信边界时采用阻断，可能增加误拦截。模型长时间不分句或账号断句行为与协议不符时，可能无法播放，需要调优或退回已验收路线。
- 进程内资源控制、部分播放文本对齐、跨节点告知缓存等 v2 已知限制继续存在。新增输出识别和审核服务额度必须计入实际并发及费用。
- 正式上线依次完成：开通并批准独立审核和 ASR 额度→固定策略/模型、准备告知→单会话真实音频及取消测试→色情/暴力/违法指导/提示注入等对抗集评测→电话端时延与误拦截评测→逐级容量与长稳→受控业务试点。通过后才启用新通话路线。
