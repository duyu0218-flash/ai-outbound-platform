# P0—P2 运营功能与验收

对照冠客录屏分析中的功能建议，在 `outbound-mono` 增量建设运营工作台。原有任务、话术画布、预约、质检和电话流程继续复用。数据库只新增 V4，不改 V1—V3；现有部署没有切换。

## 页面与入口清单

管理员新增七个入口；坐席可进入其中的查询、线索、报表、通知和个人配置。所有页面继续使用原登录、退出和租户认证。

## 状态与异常清单

- 查询：正常结果、空结果、组合条件、无效日期/时长、分页、刷新回显、详情返回、同条件导出。
- 线索：未分配、已领取、跟进中、完成、无效、到期；版本冲突返回409；同操作标识重复请求不重复落历史，变更内容返回409；批量分配遇冲突整批回滚。
- 组织：启用、禁用、成员变化、组长撤销、跨组访问；旧令牌每次请求使用当前数据库成员关系；用户禁用仍由原认证链路吊销。
- 配置：必填与类型错误返回422；旧版本发布返回409；表单旧版和已补录数据保留；视图仅本人可改删。
- 交付：失败回调可重新进入持久队列；处理中或非回调任务不可重试；不会在配置保存时发送第三方请求。
- 登录/退出：复用原认证与会话失效；未登录、错误密码、角色不符和异常页面由浏览器原有回归覆盖。

## 范围和权限约定

管理员保留全租户权限。组长由 `ops_member.is_lead` 指定，范围为当前启用组的成员；普通坐席只见本人负责的线索、人工通话和转接请求。联系人归属与待办归属分别维护。

兼容旧权限时，未配置运营团队且没有运营权限记录的原 `is_supervisor` 主管保留原全租户主管权限。纳入团队时会创建运营权限记录，撤销最后一个组也不会恢复全租户权限。上线迁移应明确将哪些原主管纳入团队。未分组旧坐席保留原未分配人工队列的接听恢复路径，但该路径不能读取其他负责人的线索，也不授予通话列表和证据的全量读取权。

同一用户属于多个启用组时，整理时间取最大值、转接等待时间取最小值，所有组都允许个人覆盖时才启用个人配置。

新坐席默认不能导出，号码展示脱敏；录音权限可单独关闭。字段脱敏针对结构化号码字段，不会自动清洗录音音频或业务人员自由填写的备注。能读证据的用户仍需按实际业务授权。

## 报表口径

运营报表明确区分会话数、会话累计拨打尝试、组内唯一号码、接通会话和接通唯一号码。合格线索只统计质检结果为 `qualified_lead` 的唯一号码，人工补录必填完成不自动判为合格。一个号码可能跨任务、坐席或时间组出现，组内唯一号码不能跨组相加为总人数。

接收转接按已接收/完成的转接记录或当前人工通话状态计数，不能作为真实媒体桥接成功证明。费用继续使用原用量及估算页面，不能当运营商结算账单。充值、套餐和企业微信原生 OAuth 不属于这次系统交付；业务连接提供已有签名 Webhook，外部授权和实际效果须联调。

## 数据和迁移

V4 新增十张运营表：ops_team、ops_member、ops_permission、ops_lead、ops_history、ops_view、ops_config、ops_notice、ops_presence、ops_tag_link。原44张应用表不变，迁移后54张应用表，另有1张 Flyway 元数据表。旧业务的列、外键、唯一键和数据层回放断言继续检查；新表数量在验收中显式加入。

正式更新前需停旧进程，备份 MySQL、对象存储和配置，再让新版本迁移并启动。V4 为新增表迁移；回退应用前先停止新进程，保留新增表与备份。禁止并行跑两个 JVM 或滚动升级。回退不能通过删除运营表实现，否则会丢分配和跟进记录。

## 关键业务链路

登录 → 导入联系人并核验同意/禁呼 → 话术画布和策略发布 → 创建、启动任务 → 模拟外呼 → AI对话 → 转人工/超时回退或预约 → 质检复核 → 线索分配与跟进 → 报表下钻和导出 → 退出。

系统没有门店、房型、购物车或支付页面，通用商城链路不适用。
