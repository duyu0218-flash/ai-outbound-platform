## 鉴权与独立凭据补充

- 火山 ASR、TTS、O2.0 实时语音支持各自的新版 API Key，发送 `X-Api-Key`，不混入旧版 AppID／Token 请求头；方舟文本模型仍使用独立 Bearer Key。
- 三个语音服务也可分别使用自己的旧版 AppID＋Access Token。旧版 ASR 修正为 `X-Api-App-Key`，TTS／实时语音按各自文档发送请求头。
- 每服务优先独立 API Key，再选独立旧版凭据；没有独立配置时才兼容共享 Key 或原共享旧版配置。独立配置缺一项时不会从其他服务或共享配置拼接；支持 `_FILE`，文件不可读时明确报告缺失。
- 通话快照固定鉴权方式和变量引用，不保存秘密值；原有无鉴权字段快照继续走共享旧版配置。供应商鉴权失败不自动更换凭据重试。
- 腾讯默认文本端点更新为 `https://tokenhub.tencentmaas.com/v1/chat/completions`，显式配置的地址仍按配置使用。
- 后台同一「语音方案对比」入口新增每服务鉴权方式和缺项显示；配置模板已同步。这次补充没有新增数据库迁移。

定向验收包含 22 项：17 组协议与原生 PCM 媒体播放场景，以及 5 项配置／协议约束检查。新增场景在真实 WebSocket 握手处校验 Header，覆盖独立新版、独立旧版、新旧混用、共享回退与新模式下旧 Header 缺席；另验证不完整凭据、密钥文件、旧快照兼容及变量引用不包含秘密值。服务端使用本机模拟供应商，并未使用实际云账号。

## 已验证项

- 全量 `mvn -o verify` 成功，耗时 7 分 06 秒：252 项单元测试、320 项集成测试，失败／错误／跳过均为零。原有浏览器 35 项与本次新增 8 项检查均通过，新增页面无 JavaScript 错误。
- Java／前端／资源／Mapper XML 格式、JDK／依赖约束及包布局检查通过，`git diff --check` 通过；Jar 启动烟测通过。Jar 哈希见机器摘要。
- 六套适配器实际发出各自协议请求；本机服务校验关键载荷、腾讯签名、识别事件、SSE 回复和音频帧。
- 六套均通过 NativeMedia 接收 PCM、识别回调、回复指令及 PCM 播放；端到端另外验证实时模式在完整回复结束前出声、整段审核模式在结束后出声。
- 服务端固定话术和模型快照；修改原话术或后续系统设置不改变已生成快照。
- 端到端实际语音回复回写为 AI 转写，幂等回调不推进客户轮次或再次触发回复。
- MySQL 新增 V20 两张样本／结果表及 V21 租户加密配置表；空库初始化、已有 V18 升级及迁移重放纳入全量验证。

## 未验证项、已知问题与环境限制

1. 未进行六套组合的付费真实 API 调用；本机未提供可用账号凭据。供应商权限、模型／音色可用性、错误处理差异及实际账单仍未验证。
2. 未进行真实电话、SIP／RTP／PBX、多轮对话、真实打断与转人工、端到端听感及录音验收；本机协议测试不能替代这些验收。
3. 当前对比入口是单轮音频样本测试，不自动拨客户号码；文字样本只测三段式文本模型与合成，端到端要求 WAV。
4. 三段式并未实现文本生成与语音合成的完全重叠；电话播放受现有输出审核和 PCM 节奏控制，页面 API 首包时间不等于电话实际出声时间。
5. 实时流式播放的整段审核可能在部分音频已经播出后中止；默认使用整段审核模式。选择实时流式时须按业务要求验收。
6. 百度 Flex 为公测权限；千问 Omni 需要实际工作空间地址；火山文本模型需要账号可调用的模型或接入点。火山端到端使用 O2.0，未实现另一套 Seeduplex 协议。
7. 测试运行中应用退出会留下结果未确认的 `running` 记录；页面提示先核对，不自动重试。样本最多 10 条，同时最多两组测试，未开展生产容量或长稳验证。
8. 验证环境为本机 macOS、JDK 21、Docker MySQL／Redis、Chromium。111 Linux 部署、数据库迁移和公网 HTTPS 页面另行验收；真实云服务未验证。现有测试服务网络仅允许回环，真实 API 联调前须受控放行供应商网络访问。500 CPS／500 在途能力不在本次验收结论内。

## 正式联调与上线前置条件

1. 根据 [接入配置](VOICE-AI-PROVIDERS.md) 填入凭据、工作空间、模型与音色，取得公测权限；受控放行供应商网络访问，再开启外部模型调用授权。
2. 按现有单实例升级规则备份数据库、执行 V20／V21、部署构建；配置 FreeSWITCH、PCM 媒体和签名回调，启用 `VOICE_AI_PIPELINE=pipecat` 与 `VOICE_AI_PROFILES_ENABLED=true`。
3. 先用同一批固定音频进行六套真实 API 对比，再用专用测试号码完成开场、业务多轮、拒绝、打断、转人工和结束通话验证；核对实际录音、时间和账单。
4. 根据真实结果选定默认方案及播放模式，补齐目标环境容量、长稳、故障恢复和发布验收后再开放正式外呼。
