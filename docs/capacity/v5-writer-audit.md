# v5 写入者与启用门禁复核（进行中）

本表来自当前源码只读追踪，不是所有路径已通过并发门禁的证明。当前保留 `lock_compat` 和既有全局安全边界；政策入口增加 `PolicyWrite`（事务前获取同一平台锁）；不能因个别批处理通过就启用 db 去锁。用户最新授权为功能回归通过即可更新 GitHub/main，并注明性能未达标；容量门禁仍未通过，禁止部署。

|---|---|---|
| 单号、异步批量与号码池准入 | 平台锁、控制屏障、租户行、电话行及预留触发器 | 所有入口共享政策版本、日计数和硬配额；异步 202 不代表实际拨号接受 |
| 联系人创建、修改、DNC、批量 DNC、删除 | 事务前平台锁、租户共享行；冻结触发器 | 已把删除的普通查询移到锁后；与同意撤销/号码变更/准入的完整并发矩阵仍须复验 |
| 租户 compliance/capacity 设置 | 事务前平台锁、租户共享行；冻结触发器 | 真实线路检测移到共享边界后；新增容量下调保护与已提交准入竞争用例通过；直接 SQL/多进程政策协议尚未闭环 |
| 线路创建、修改、禁用 | 事务前平台锁、租户共享行；冻结触发器 | 新增 max_concurrency 下调保护实际 HTTP 回归通过；完整禁用/最后配额/旁路写入竞争仍待验证 |

| 初始与终态回执 | 分区/电话行；终态仍保留平台资源锁 | 保持原轮身份、补确认、AI 与用量幂等；回执大小写历史已修复并定向验证 |
| 转人工、人工拒绝、FIFO 再分配 | 保留平台锁、电话/坐席/任务与持久配额 | 坐席/线路/活动/租户/平台的完整顺序，含隐式外键锁，不能仅检查显式锁 |
