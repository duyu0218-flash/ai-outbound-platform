# V3 实时任务积压与停止发压排空验证

## 修改入口和状态清单

本批围绕 F03 的单 JVM `lock_compat` 路径修复。不启用 S1 新配额权威，不移除共享保护，不部署。它不代表 V3 所有阶段或持续 500 CPS 已通过。

| 入口 | 变更与应验状态 |
| --- | --- |
| TaskWorker 定时调度 | AI、播放/定时/打断、结束后分析及集成独立执行池；每个逻辑 owner 最多一段待执行任务，队列有界。实时任务和冷分析分别使用独立且有上限的 Druid 连接池 |
| 播放后控制 | 固定的租户/通话哈希分区在当前 JVM 中保持同一通话串行，不让未来定时器阻塞到期控制；原任务租约、attempt/generation 检查不变 |
| 数据库连接 | 默认业务池4、实时池4、分析池1；同一数据库及同一 Spring 事务资源键，嵌套切换提示不拆分事务 |
| 实时队列压力 | 只读取已到期的 AI/播放/打断任务，包含 PROCESSING；控制年龄0.1秒开始减速、0.5秒停止新增；AI年龄0.5秒开始减速、1.5秒停止。实时死信或取证不可用时停止新增，保留在途消费者 |
| 可靠终态回执 | 整批回执写入后在同事务按至多100个通话一次查询和批量完成同租户、同通话、同 attempt 尚未领取且已失效的 AI/控制任务，记录 superseded 原因；不删除原任务，不覆盖 PROCESSING、DEAD、预约或其他 attempt |
| 停止新增准入 | begin 在旧平台锁和持久屏障下捕获固定在途集合；停止 enqueueDue 新队列补充，未准入号码仍保留 |
| SEND_CLOSED | 保留持久命令查询和确认，停止新发送；不停止 AI、定时器、终态、inbox/outbox 或分析消费者 |
| 短测 | 使用独立 ShortMockDrainProbe；原 MockDialRate500Probe 的 500 CPS 失败断言保持不变 |
| 页面与登录 | 没有修改界面；仍须跑 Chromium 登录、退出、入口、表单保存回显、权限及异常回归 |

本项目是外呼平台；首页→搜索→门店/房型→购物车→支付的电商链路不存在，不能声称验证了该链路。实际业务入口由现有浏览器回归及 HTTP/集成测试覆盖。

## 排空验收合同

1. 同上一轮诊断使用 40 秒预热、30 秒观察、20% 确定性接通、20 秒模拟占线、预装号码池、真实隔离 MySQL/Redis 和规则 AI。记录实际线程、池、数据库参数和构建哈希。
2. 正式观察窗口结束后关闭新增准入，持久化固定在途集合；发送/未知命令未确认时不得跳过 close-sending 门禁。记录停止请求、屏障结果及最终发送关闭的观测值。
3. 在同一进程继续消费生命周期工作。未准入 queued 号码及其尚未占用的 dial_call 任务属于保留队列，不计为已准入生命周期工作；已存在持久命令的 dial_call 确认仍必须完成。
4. 每秒使用一致性只读快照记录业务/网关在途、必需任务、dial PROCESSING、inbox/outbox、死信、reservation、号码互斥和平台/网关活动计数；任务分开记录到期、未来及处理中，不能把总数都解释成逾期。
5. 在 180 秒有界等待内，全部必要项连续三次为零；不强制挂断、不删任务、不冻结进程来伪造归零。之后才调用隔离 mock 的冻结检查。
6. 按 K=(tenant,call,attempt) 双向核对网关身份、唯一持久接受事件、业务终态及 ended 用量事实；发送关闭后尝试数不能增加，各类活动资源余额为零。
7. 另报吞吐及任务到期至完成的延迟诊断。排空通过不抵消稳态逾期，不把 `diagnostic_passed` 或 `stop_drain_verified` 当作 `capacity_qualified`。事件 created_at 分桶仍只是旧诊断，不是独立提交时间证据。superseded 数量及发生在原计划时刻之后的数量另报，不能把这些任务当成成功派发。

## 本批边界

- 四个播放控制 owner 是当前单 JVM 内的固定分区；不能当作跨进程分区 epoch、全部网关安装屏障或多实例所有权实现。owner 数量须随停机/排空重启变更，不能解释为运行时在线重分区。
- 线程及连接预算已隔离；默认业务连接上限合计9，加独立网关账本4，共13；启用独立证据池时再加2。实际 MySQL CPU、IO、行锁和旧准入串行锁仍共享。冷分析暂停 30 分钟、独立连接/IO预算、事件到动作持久派发 P99≤500ms/单次≤2s 与全量 AI 期限等 V3 门禁仍需独立证据。
- 无真实 SIP/RTP、音频、ASR/LLM/TTS 配额；本地规则模拟不能证明供应商或生产资格。
- 原始数据库、JFR、日志和结果只保留在本地忽略目录；上传源码、测试和脱敏结论。

### 延迟和剩余失败门槛

- after_playback从available_at至完成：P99 **961ms**、最大 **1,555ms**，超过2秒的为0。本项统计没有大于2秒的完成样本；完成时间包含派发后的工作，不能由此判定实际派发P99已经失败或通过。500ms门槛尚不能签署。
- ai_turn从available_at至完成：P99 **1,977ms**、最大 **2,059ms**。全部712个已处理，本轮没有AI任务在终态后被替代；这不能证明后续轮次P95或独立事件到动作派发SLO。available_at在任务重试时会改变；正式验收还须保留原始期限和每次尝试，不能只用此完成时延签署硬上限。
- 冷分析在负载结束时仍有994项积压，尾部已排空；完整工作周期内是否收敛、存储预算和冷消费者暂停30分钟仍未验证。
- 27.2 CPS与此前230.3 CPS使用不同的线程/连接预算及实时保护逻辑，不能解释为严格同资源A/B。新增的默认业务连接上限9（4+4+1）已经单独记录，不把增加资源隐藏为算法收益。
- 第一轮实现曾出现批次写入被逐通话清理打断及共享连接争用，短测30.4 CPS；修正批量清理和连接隔离后第二轮85.2 CPS，但控制尾延迟仍过大；最后加入到期年龄反馈，收敛实时积压而吞吐继续受限。这三轮均未签署容量资格，原始证据全部保留，不挑选峰值作为结论。

原始本地证据在 `outbound-mono/verification/v3-backlog-short-r1/`、`v3-backlog-short-r2/`、`v3-backlog-short-r3/`。最新r3/short-summary.json保留固定秒、各阶段尾部及资格标签。短测JAR SHA256为 `2041da0ba0e4dd32e20e6f08b8e8ee8a97c33d667ffb503052e1c83958fa1f65`。
