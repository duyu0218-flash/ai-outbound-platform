S0 的完整写入者清单与当前构建耗时归因仍未签署退出；本批是隔离协议原型，不代表已通过 S0 或可启用新准入。下阶段须先完成这些证据，再推进实际接线和去热点。

`DurableQuotaCoordinator` 当前没有公开 HTTP 管理入口或定时回收任务。作用域只允许并发资源，不将日计数/CPS 伪装为可退回的并发额度。消费使用 reservation 身份，K 的活动唯一约束在 MySQL 中执行；可靠撤销后可为原 K 创建新的 reservation，旧身份重试只能返回原结果。

## 事务合同

- 发放、消费和释放返回时，各自独立事务已提交；不能因外层业务事务回滚丢掉已经返回的预算。
- 消费/释放的回调仅允许通过同一 DataSource 持久业务事实，不得调用网关或执行外部 I/O。回调失败，配额与业务事实一起回滚。
- 顺序为协调器、grant、allocation、按 scope_key 排序的并发范围。所有权切换须取得协调器排他锁，等待旧操作结束；恢复不依赖分片上报。
- `held = OPEN grant 的 issued-consumed + ACTIVE allocation`。过期 OPEN grant 仍占用；关闭只减未用单位。已发送或未知 ACTIVE 必须等可靠终态/未发送证明，不能按心跳或 TTL 释放。
- `recover` 核对各 grant 的消费身份数量和完整范围清单；差异使恢复失败，不能进入 READY。
- 这不是跨 AZ RPO=0 实现，也未解决所有权栅栏、策略更新屏障和旧路径额度桥；不得启用为生产权威。
