# 消息营销与语音 v2：当前实现及接入说明

消息模块在既有 Java AI 外呼系统内运行。现已新增 HTTP 接入规范 v1、进程内 SMSGate CMPP 3.0、四种消息形态的模板与富媒体内容、通道审核、真实协议发送/回执及对外 API 扩展；保留独立 mock 用于测试。供应商尚未选定，**本地功能验收不等于供应商兼容或手机实收验收**。最新配置、协议边界及验收步骤见 [HTTP / CMPP 接入说明](message-channel-bridge-v1.md)。本次没有使用 Austin。

完整目标架构见 `marketing-messaging-architecture-v1.md` / 同名 Word；`messaging-target-design.openapi.json` 是目标草案。**当前对接使用 `messaging-implemented.openapi.json`**，不能混用草案中的响应包裹、代理商委托、能力探测等尚未开放字段。原始语音方案保留为 `voice-streaming-v2-source.md`，其中“本次只更新文档”等描述属于原文历史状态；语音 v2 历史验收见 `../reviews/20261028-marketing-voice-implementation.md`；本次消息扩展验收见 `../reviews/20261106-message-channels-acceptance.md`。

## 数据与一致性

基础消息表为 Flyway V25～V28，本次新增 V46 通道、分片、回执、素材和对账表；只新增消息表和字段，不删除旧表。`msg_message` 的待提交状态即持久工作队列，消息、冻结账本与事件同事务提交。`msg_attempt` 保存通道尝试，`msg_inbox` 保证回执幂等，`msg_batch` 保存批次及逐项结果，`msg_call_intent` 保存通话联动意图。`msg_webhook` / `msg_webhook_delivery` 独立管理回调，不重用业务发送重试。

每个企业用数据库租户行锁串行校验与记账。消息进入 SUBMITTING 后才调用适配器；进程在外部提交边界中断，超过两分钟转 UNKNOWN，保留冻结余额，等待核查或迟到回执。**不会因为 HTTP 超时自动再发。** HTTP 适配器通过查询补偿，CMPP 通过真实分片回执和运营商核查恢复；原生供应商需遵守接入协议，不能通过把 UNKNOWN 改回 QUEUED 实现重试。

同企业应用共享账户，每个下游企业必须独立建租户。商业上下级不产生数据访问权。本版本拒绝 `X-Delegation-Id`；多级代理委托、授信、支付网关充值、发票、分账及合同资费版本尚未开放；生产人工凭证入账另见通道说明。

日期以 UTC 保存，开放消息、批次和事件查询使用 UTC ISO 8601。数据库时区必须为 UTC；时钟同步是签名与调度前置。消息精确金额用 BIGINT 微元，1 CNY = 1,000,000 微元。模拟充值不与支付系统相连。

## 启用与回退

默认配置全部关闭。仅在隔离开发/测试环境设置：

```text
MESSAGING_ENABLED=true
MESSAGING_WORKERS_ENABLED=true
MESSAGING_WEBHOOKS_ENABLED=false
MESSAGING_MIGRATE_CALL_SMS=false
MESSAGING_MASTER_KEY=<独立生成的 32 字节随机值的 Base64>
MESSAGING_RETENTION_ENABLED=true
```

回调确需联调时启用 `MESSAGING_WEBHOOKS_ENABLED`；外呼迁移前先批准 `call_rule`，再启用 `MESSAGING_MIGRATE_CALL_SMS`。两者均不是启动消息页面的必要条件。生产模式拒绝 mock 发送和模拟记账。不要复制测试中固定零字节密钥到实际环境。主密钥通过现有统一配置文件/密钥设施注入；AES-GCM 绑定租户和资源上下文。应用密钥支持轮换及旧钥宽限期；当前没有在线主密钥轮换工具，换钥前必须完成密文重加密及号码哈希迁移，不能直接替换配置。

回退先关闭消息与回调 worker 以及外呼迁移开关；保留数据库新表、未知消息、账本和密钥。旧短信路径保持原行为，不能同时重放已迁移意图。不要删除新表来回滚已产生的数据。语音运行时回退按现有单实例停旧启新流程，先停止新准入并排空在途；本次没有将媒体服务改成多实例。

## 下游接入

企业管理员在“内容与主体”建立并批准产品、主体和模板，在客户管理保存有效授权联系人，再到“应用接入”创建授权应用。密钥仅创建/轮换时展示；撤销后不可继续签名。没有公开的自助匿名开户接口。用于再分发的一个客户对应一个租户及其应用，平台统一持有未来上游密钥。

签名原文为以下 8 项以 LF 连接，最后一项是空字符串（所以有一个尾部 LF）：

```text
METHOD
/openapi/v1/path
canonical_query
unix_seconds
nonce
sha256(raw_body)
idempotency_key
<空委托上下文>
```

查询参数先解码、拒绝同名参数，按参数名排序，再按 RFC3986 编码为 `key=value`；GET 无请求体时对空字节取摘要。HMAC-SHA256 使用应用 secret 的 UTF-8 字节，输出小写十六进制。请求头详见实际 OpenAPI。SDK 示例 `outbound-mono/tools/message-api-client.mjs` 不自动重试；网络未知时保留原业务键及原始业务内容，用新时间戳/nonce 重新签名提交完全相同的请求，取得同一消息。不要重算有效期或更换幂等键。

`202` 只表示受理。`GET /messages/{id}` 查询业务状态；`GET /events?after=<sequence>` 每次最多 200 条，用最大序号接续。事件通常保留 30 天，未推进回调游标的事件延长保留；超出保留窗口必须以消息状态重新核对，当前没有历史归档查询或游标过期错误接口。

批次的每个 `client_item_id` 稳定且唯一，逐项受理或拒绝，失败项不会因重新查询自动再发。`/message-batches/{id}/items` 当前返回含 results 的完整批次对象。所有发送的渠道策略只选择已批准产品的形态，`allow_fallback=true` 返回冲突错误；`automatic` 仍只有该产品的一个固定通道候选，不代表真实终端探测。

## 回调接收

创建订阅后先返回 PENDING_VERIFICATION。平台发送 `webhook.verification` JSON，将 challenge 通过接收方响应头 `X-Webhook-Challenge` 原样返回，成功后才投递业务事件。密钥只在首次创建返回，重复创建不会再次泄露密钥；丢失应停用后新建。验证失败可查询 VERIFICATION_FAILED，排错后停用旧订阅再创建。每应用最多 5 个未停用订阅。

签名头 `X-Signature: v1=<hex>`，签名原文 `timestamp + LF + event_id + LF + sha256(raw_body)`；接收方同时验证时间窗和持久 event_id 去重。业务回调内容是 `event_id/sequence/type/data`，同一事件重试内容固定。仅 2xx 确认，拒绝 3xx 跳转。最大发送 12 次或存活 24 小时后 DEAD，指数退避最高 1 小时；失败投递可用事件拉取补偿，不重发手机消息。已支持 DEAD/PENDING 投递人工补发，未实现 Retry-After 自适应。

回调出网限制 HTTPS 443；每次重解析并校验所有地址，拒绝私网、回环、链路本地等，实际 TLS 连接固定在已校验 IP，校验原始主机名。DNS 等待最多 3 秒，连接与读写关闭期限 5 秒。部署还需出站防火墙。回调 worker 单独线程执行，网络延迟不会占用外呼或消息发送线程。

## 语音 v2 落地范围

- 共享 HTTP 客户端归服务生命周期；百炼试聊、控制器、媒体调用与内容审核复用连接，服务关闭时清理。
- SSE 按字节块读取并严格 UTF-8 解码，限制行/事件/总量；首有效文本、内容空闲、总时长分别超时，心跳不延长内容期限；每响应一个定时任务，关闭传输不阻塞公共计时线程。
- ASR 输入按会话使用有界准入的虚拟线程发送，保留顺序、字节所有权和缺口证据；VendorSocket 错误收尾取消发送及接收。
- TTS 生成与 PCM 发送通过响应专属有界队列解耦，约 1.5 秒缓存，队满超时受控失败，不能任意丢播放帧；发送 drain 后再完成，保留旧 epoch fence。
- Outbox 事务提交后增加唤醒提示，持久轮询仍承担恢复；提示失败不推翻已提交事务。
- `VOICE_PARTIAL_TRANSIENT_ENABLED=false` 默认保留旧 partial 回调；启用后普通 partial 保留媒体侧，final 和紧急控制意图继续持久回调。现有依赖逐条 partial 的消费者必须先迁移，未新增前端逐字推送协议。
- 审核许可等待有界且检查取消；未放宽句子审核、S2S 音频审核、未知拒绝或先审后播规则。

配置 `VOICE_LLM_FIRST_CONTENT_MS/VOICE_LLM_CONTENT_IDLE_MS/VOICE_LLM_TOTAL_MS` 默认 1500/2000/15000 ms；审核队列 `VOICE_AI_SAFETY_QUEUE_MS` 默认 100 ms、最高 500 ms。以上是运行配置，不是已取得的真实电话体验指标。

尚未完成目标 v2 的真实百炼电话适配、共享供应商 QPS 调度、多实例 owner/fence、目标硬件混合容量、8/24 小时长稳与真实手机端时延验收。这些需要线路、供应商账号、配额与环境；不得把本地功能回归当作其通过证据。
