### HTTP 写入压测

本机 Mac、隔离 Docker PostgreSQL/Redis、单 API 进程；6 个数据库连接、overflow 0、总请求名额 6、Webhook 名额 4、无等候队列。调用真实签名 status Webhook，每条请求均使用不同且存在的合成话单，后台内联执行关闭。

| 输入负载 | 首次响应 | 成功 HTTP p95 / p99 | 客户端实际峰值 |
|---|---|---|---|
| 50 RPS × 15 秒 | 750/750 为 200 | 24.48ms / 27.06ms | 3 |
| 100 RPS × 15 秒 | 1491 为 200，9 为受控 503 | 19.76ms / 40.57ms | 5 |

100 RPS 试验不能标记为全部首次成功。9 条拒绝按原事件 ID 重试后均成功，核对得到 1500 条完成话单及恰好 1500 条去重凭据。客户端配置上限 500，不代表实际有 500 条并行请求，更不代表 500 路音频。

1. 备份主库；在预生产执行 `python -m app.schema_bootstrap`、`python -m app.migration_runner`，包括新迁移 `20260907_capacity_bottlenecks.sql`。运行时生产仍禁用自行改表。
2. 排空媒体节点后升级；先部署兼容新语音代次字段的网关和对应受限拨号计划，再升级使用新任务类型的 worker/API。旧 worker 不消费 `dial_call` / `after_playback`；不得只更新 API。
3. 四节点 `nodes.json` 明确填写 CPS，不高于该节点及所有授权线路的最低 CPS。保持已有通话归属，未知 PBX 状态不释放容量。坐席 registrar 映射必须与浏览器真实注册位置一致。
4. 录音适配器的来源允许列表加入四个节点专有录音源；下载链接带时效签名，限制日志记录完整签名 URL。验证只读录音目录、下载并发、对象存储和失败补录。
5. 从真实工作负载采集通话时长、接通率、终句间隔、AI 平均任务占用时间，再运行预检。若 500 路每 4 秒一轮、平均 AI 占用 3 秒，70% 目标利用率所需总槽为 536；N-1 当前只有 192，预检会拒绝。这一场景需要缩短模型/任务耗时或提升经过资源及配额验证的执行预算，不能靠将目标数写为 500 放行。
6. 单节点真实音频按 20→50→100→150→200 分档，200 路至少 8 小时；四节点 500 路长稳、同步终句、打断、转人工、录音、数据库/Redis/节点故障与滚动排空。确认模型 QPS/TPM、首音、音频间隔、队列年龄和资源余量达到验收值。
