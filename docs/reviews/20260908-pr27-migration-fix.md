# PR #27 合并前迁移修复

## 问题与修复

GitHub CI `34244463915` 的 PostgreSQL/Redis 作业中，269 项后端测试通过、2 项跳过，但随后执行版本迁移出现 `callbackinboxpartition.pending_count` 非空约束错误。模型建表只有客户端默认值，原迁移的分区初始化 INSERT 依赖数据库默认值；即使分区已存在，非空检查也会先于冲突忽略执行。

新增 `20260908_callback_00_partition_defaults.sql`，排序在原 Inbox 迁移之前，为已存在的分区表补齐两个计数列的数据库默认值。未修改原迁移文件及校验值，未更新已有计数或业务数据。空库由后续 Inbox 迁移正常建表。

## 涉及入口与状态

- 数据库初始化后执行 `python -m app.migration_runner`：模型建表、空 schema、重复迁移。
- 回调分区：补齐 64 个分区、新增分区初值为零、已有非零计数保留。
- 页面、表单、登录、退出及导航没有修改；本次变更的验证入口是数据库迁移命令。

## 已验证

- `git diff --check`、版本约束和兼容矩阵检查通过。
