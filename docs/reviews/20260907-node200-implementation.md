# 单机 200 路架构改造与隔离验收

实施时间：2026-09-07 至 2026-09-08。基线 `f1ec088`，分支 `fix/review-p1-p2-20260907`。

**本轮完成了控制/媒体拆分、异步 AI 执行、四 API 逐请求分流及部署配置。200 个合成通话状态的对话事件测试通过；真实单机 200 路及四机 500 路尚未验收，不能作为上线容量保证。**

沿用四台应用宿主机、自有业务平台与 FreeSWITCH/Pipecat，托管 PostgreSQL/Redis/对象存储及云模型基础服务。运营商已有 500 路能力作为前提。增加的是同机进程/容器，不增加应用服务器台数。

## 落地内容

| 部分 | 最终实现 |
|---|---|
| 媒体 | 一个 PBX 控制者 + 四个独立媒体进程，每进程 50 名额；FS 直接连接指定进程的 PCM WebSocket |
| 归属与恢复 | 创建前以 SQLite FULL 持久保存 call/attempt/worker/epoch/session/token；重启恢复原归属，旧 epoch/会话/轮次拒绝；未知占用保留，只有确认关闭或新 epoch 才清除媒体归属。PBX 全局名额仍按原独立安全账本对账 |
| RPC 与回调 | 本机独立 token 鉴权；命令期限；同语音代次的播放去重与内容冲突拒绝；关闭先于创建时防复活；旧媒体未关闭不能复用于重拨，并发关闭与晚到回调不能误操作新会话。媒体事件需控制器持久确认后才 ACK；有限重试仍失败时标记媒体故障并结束受影响呼叫 |
| AI | 两个独立异步 worker，各 128 个任务；准备数据、异步模型等待、结果应用分开。每进程 2 个 DB 线程 + 2 个动作线程、最多 3 个 DB 连接；每秒检查陈旧模型请求，保留最终轮次、输出审查和租约校验 |
| 后台 | background 角色不再领取 ai_turn；禁止通过别名重新混入 AI 通道。录音、质检、业务回调与播放续接仍为有界通道 |
| Agent | 外部模型连接池可配置，compact 为 256 连接 / 128 keepalive |
| API | 四个单进程、独立端口 8010–8013；同机 NGINX least_conn 分流，禁止代理自动重试 POST；每进程总执行 4、回调 3、普通请求 1、等待 8 / 50ms、DB 池 4 |
| ESL | 按通话 FIFO、跨通话公平轮转；总接收预算 2048，32 个处理任务。避免旧 hash 分区满时阻塞不相关通话；全局饱和仍停止新拨号并背压，不能宣称永不阻塞 |
| 运维 | 单进程运行指标独立抓取，AI 容器本地心跳，媒体指标由控制器聚合；新增 PBX 会话腿数、创建速率与 RTP 端口静态预检 |

数据库运行池预算为每机 `4×4 + 2×3 + 2 = 24`，四机 96，另留启动、运维与采样连接。没有引入额外 DB/Redis 服务器。

当前非可选容器 CPU 限额合计 23、内存限额约 29.25 GiB。这是限制配置，既不是资源预留，也不是实测需求；原 16 vCPU/32GB 不能作为单机 200 路保证规格。目标服务器仍须对全部组件同时运行时的 CPU、内存、磁盘、网络和音频时序做资格验证。

## 实测结果

环境为本机 macOS Python 3.12、隔离 Docker PostgreSQL 16 / Redis 7；NGINX 镜像摘要为 `sha256:dc5069ad14f19660b141b21236140b91656bf89bbc3e2417c70ae650cd66104c`。Docker Desktop 代理跨到本机 Python 进程，不能当成目标 Linux 宿主机硬件容量。

### 合成对话与异步处理

- **对话混合测试**：200 个合成 IN_AI 通话状态，50 最终转写/秒 + 100 媒体事件/秒，持续 30 秒，模拟模型固定等待 3 秒。四 API 与两 AI worker 同时运行。
- 4,500 个回调均首次 200，无重试；回调 P99 39.06ms，发压调度延迟 P99 1.34ms。
- 1,500 条最终转写、1,500 个 AI 完成任务、1,500 条成功 AI 指标；模型峰值在途 158，测试结束后任务排空，总耗时含排空 33.11 秒。
- **同步模型等待**：两个真实 AI worker 同时到达 256 个模拟模型请求；256 个持久任务全部一次完成。此为等待并发测试，不是 256 个真实通话或供应商吞吐验证。
- **数据库隔离回归**：20 个模型同时被测试栅栏阻塞时，已借出 DB 连接为 0，DB 工作线程不超过 2；通话结束取消模型等待，取消的工作单元不能继续产生副作用。多进程 DB/模型指标是非原子采样，不把瞬时事务采样误解释成长时间模型持锁。
- **四媒体进程**：真实启动四个 Pipecat worker，各创建 50 个合成控制会话；拒绝第 201 个，控制器归属恢复一致。重启一个 worker，仅其 50 个旧归属失效，其他 150 个保留，再补入 50 个。未打开真实音频 WebSocket、未拨号、未调用 ASR/TTS。

### API 对照与明确未达标项

以下为 status-only 终态回调，每个成功事件创建一份话后质检任务。常规对照关闭消费者；最后一行开启两个真实质检消费者。

| 配置 | 速率 / 时长 | 首次成功 | 受控 503 | 排队至完成 P99 |
|---|---:|---:|---:|---:|
| 两 API，各池 6 | 100/s，30s | 3,000 | 0 | 31.61ms |
| 两 API，各池 6 | 200/s，30s | 5,995 | 5 | 66.12ms |
| 两 API，各池 6 | 400/s，30s | 7,323 | 4,677 | 97.84ms |
| 四 API，各池 4 | 200/s，30s | 6,000 | 0 | 48.59ms |
| 四 API，各池 4 | 400/s，30s | 9,878 | 2,122 | 107.30ms |
| 四 API + 质检消费者 | 200/s，120s | 23,717 | 283 | 70.40ms |

分流基本均衡，不能再把全部限流归因于长连接偏到单进程。**400/s 余量门槛仍失败**；没有通过扩大无限队列或取消保护来改写结果。

所有失败事件以原标识重试，重复回放不增加重复业务记录；最终话单、事件收据与质检任务数量一致。最后一行回调重试完成时，24,000 个任务中完成 4,260、待处理 19,740，说明两个质检消费者明显跟不上 200 次挂断/秒。未声称该队列已排空。

每秒结束 200 通电话并不等于同时接通 200 路。单机 200 路的日常话后任务速率应按接通时长与挂断分布计算；大批同步结束仍需单独测排空时间。后续须对真实回调组合、数据库尾延迟、质检吞吐及模型限流作剖析，而非机械把线程或连接设为 200。

## 文件、复现与发布

- 拓扑：`docker-compose.compact.yml`、`deploy/compact/nginx.conf`。
- 运维与升级入口：[compact 使用说明](../../deploy/compact/README.md)。新增 `API_PROXY_IMAGE` 和每机独立 `MEDIA_RPC_TOKEN`；原控制器、媒体、模型和节点配置必须一起核对。
- 媒体进程合成验收：`scripts/load-node200-media-processes.py --output artifacts/node200/media-processes.json`，使用网关 Python 环境。
- 双 AI 进程合成验收：`scripts/load-node200-ai-processes.py` 与 `scripts/fixtures/node200_agent_fixture.py`，使用后端 Python 环境。要求显式准备回环 15443 的独立空 PostgreSQL 库（用户 node200，公开测试密码见脚本）及 16443 的测试 Redis；`NODE200_TEST_DB` 可指定以 node200 开头的新测试库。脚本不清空既有数据。
- PBX 静态检查：`scripts/check-node200-pbx.py`，输入运营提供的已展开 core XML。默认按 200 客户、两条腿、100 余量核算；仓库 20 路联调 XML 会正确拒绝，原件未改。
- 结构化证据与源码指纹：[证据 JSON](20260907-node200-evidence.json)。原始本机过程文件在未入 Git 的 `artifacts/node200/`，包含压测夹具、逐进程运行采样与结果。

发布前先排空一个**物理节点**，等持久通话与待发回调归零，再整体升级该节点的控制器和媒体进程。禁止直接把整个网关设成四 workers；禁止活跃期间修改 worker ID、端口或 token。新增媒体归属表由唯一控制器在其本地账本创建，没有本轮新增 PostgreSQL 业务迁移。
