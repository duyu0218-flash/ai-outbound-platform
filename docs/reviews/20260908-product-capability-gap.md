# 自有 AI 外呼产品能力与特殊场景差距

分析日期：2026-09-08。代码基线：`547abb4`，分支 `fix/review-p1-p2-20260907`。

目标是用自有平台交付业务，运营商已有 500 路能力作为前提。本报告比较产品行为，不评估运营商容量，不要求采购或集成阿里云、腾讯云外呼平台。可继续使用云 ASR/TTS/LLM 基础服务。

结论：优先补齐“听懂业务意图并执行正确动作、特殊接听处理、无应答与异常兜底、转人工等待策略、可靠结果交付”。现有管理页面、禁呼设置、流程版本、录音与人工复核应复用。不能把已有字段或接口当成相应场景已经完整实现。

## 已有能力：不要重复建设

- 客户、活动、话术、话单及角色权限已有实现；最近一轮有浏览器入口与保存回显验证。
- 拨号前已检查禁呼、同意状态、时区、每日次数和触达间隔；已有人工批量禁呼入口。缺口在通话中识别诉求并自动形成业务动作。
- 话术流程已有草稿、发布、不可变版本、克隆和单步模拟；缺口在节点表达能力、业务测试和统一版本追溯。
- 有多轮历史和知识条目检索。阿里云 NLS 已有 vocabulary_id、customization_id、语义断句及静音阈值参数；缺口不是“完全没有热词/断句”，而是按业务配置、使用正确性和效果验证。
- 打断、媒体归属、过期回复拦截、重试和失败记录已有工程实现。
- 转人工已有坐席在线状态、接受/拒绝、失败回到等待状态、摘要与最后一句展示；缺口不是“没有转人工/上下文”。
- 话后分析、人工复核、录音资产、回调重试及死任务补偿已有实现；缺口是业务判定和交付完整性。

## 本轮实际复现

使用当前后端函数与内存 SQLite 合成记录，无业务数据、网络拨号或云模型调用。关键词流程用本轮构造的有效测试图，不能推断所有已配置话术都会走相同分支。转人工测试执行从当前源文件抽取、未改写的 is_handoff 函数，使用仓库默认关键词。

| 输入/配置 | 实际结果 | 产品问题 |
|---|---|---|
| 客户说“可以听一下” | interested / positive_lead | 允许继续说不能直接等同有效业务意向 |
| “你说的是需要先交钱吗” | interested / positive_lead | 提问中的“需要”被当成肯定意向 |
| “我不需要，不对，我现在需要” | rejected / not_interested | 没有理解更正关系，需要结合上下文确认 |
| “我需要你们别再打” | interested / positive_lead，同时附 customer_compliance_risk | 风险标签与正向结果冲突；没有在此路径执行禁呼 |
| 流程正向关键词只有“需要”，客户说“不需要” | 命中正向关键词分支 | 子串匹配不能正确处理否定 |
| 默认转人工关键词，客户说“不用转人工” | is_handoff=True | 否定转接仍命中转接条件；Agent 在模型生成前作出该决定 |

## P1：替代业务交付前优先补齐

P1 表示本项目的交付优先级，不表示每项均已被证明造成生产事故。

### P1-01 意图、否定与真实业务动作

**现状：部分实现。** 默认 Agent 用关键词决定转人工，模型返回主要是待播报文本；模型说“已经预约”“再见”并不自动形成预约或挂断。流程模式有挂断节点，但不等于大模型模式能按业务意图结束通话。

**补充：** 建立明确的业务动作：继续询问、澄清、结束、停止触达、预约回拨、转人工。处理否定、反问、更正、多意图和不同意图冲突；模型提出动作后由服务端校验权限、参数、当前通话和幂等性。不要只把关键词名单加长。

**场景：** “不用转人工”“别再打了”“不是我本人”“打错了”“明天下午再打”“先别挂，我还有问题”“谢谢，再见”。

**验收：** 否定转人工不触发转接；明确停止触达落到租户内号码级禁呼并阻止待拨/重拨；打错号码与拒绝购买分开；回拨时间确认后可查询、修改、取消；动作未保存或执行失败时不能播报成功。禁呼优先于后续营销动作，模糊拒绝进入澄清或人工处理，不能一概永久禁呼。

证据：[策略](../../agent/app/policy.py:40)、[Agent](../../agent/app/main.py:54)、[拨前策略](../../backend/app/services/call_service.py:136)、[业务模型](../../backend/app/models.py:139)。未找到会话内预约对象、动作执行及自然语言撤销禁呼的完整路径。

### P1-02 业务字段采集与线索判定

**现状：部分实现且已复现误判。** 话后分类使用正负关键词；structured 内容主要是轮数、风险词和状态。已有人工复核与自动结果保留，但不是按场景配置的线索资格模型。

**补充：** 配置每个业务的必填字段、类型、条件、确认规则、证据片段和未知值。以卖车业务举例：是否本人、是否有出售计划、车型、城市、时间、价格条件、是否同意联系应分别存储；“愿意听”“允许回电”“同意评估”“确认预约”分开。支持客户更正，不能用旧信息覆盖最终确认。自动通过/自动排除/人工待确认的边界应由业务样本定义。

**验收：** 上述四个话后反例按业务规则正确处理；必填项缺失不能判合格；疑问句不当承诺；结论可追溯到客户原话、轮次和证据时间。跨重拨的历史与本次结论分开记录，明确哪些历史事实可以继承。当前 analyze_call 查询未限定 attempt，需要补充本次/累计结果的语义设计。

证据：[分析规则及取数](../../backend/app/services/call_analysis.py:15)、[分析模型](../../backend/app/models.py:365)。

### P1-03 静默、拒识与低置信度恢复

**现状：部分实现。** 有静默分支和进程/会话超时；没有看到面向节点的“播放完成后开始计时—多轮提醒—退出”完整产品策略。ASR 置信度已保存，但最终转写入队 AI 的路径没有按置信度区分澄清。

**补充：** 节点级和全局兜底：多久开始提醒、提醒几轮、用什么话术、最终转人工还是结束；低置信度、空转写、答非所问分开处理。“稍等一下”采用有限延长等待，不应立即重复提问。

**验收：** 播放中不启动无应答倒计时；用户开始回答取消旧计时器；噪声造成空转写不推进业务；连续听不清时有清晰退路；通话已结束后旧提醒不再播放。

基线：[阿里云对话策略](https://help.aliyun.com/zh/outboundbot/dialogue-strategy)。代码：[流程](../../backend/app/services/dispatcher.py:141)、[最终转写处理](../../backend/app/api/routers/webhooks.py:411)、[媒体流水线](../../voice_gateway/app/pipecat_pipeline.py:325)。

### P1-04 非真人与特殊接听

**现状：缺完整识别与处置链路。** 有 voicemail 枚举和外部状态映射，但当前自有 FreeSWITCH 路径按信令原因分类，未找到电话助手、语音信箱或分机提示识别接入。依赖库里存在检测工具不代表项目已使用。

**补充：** 区分信令接通、真人有效交互、电话助手、信箱、分机提示和无法确认；按场景选择结束、允许留言、合法配置的分机后续操作或人工处理。识别不确定时保留未知，避免误杀真人。

**验收：** “请在滴声后留言”“我是机主的电话助理”“请输入分机号”、长提示音、真人模仿提示语都有测试；非真人不能计为真人有效交互或有效线索。空号、停机、暂时不可达采用不同的重拨策略，不把所有 failed 都短间隔重试。

基线：[阿里云特殊情况处理](https://help.aliyun.com/zh/outboundbot/product-overview/product-update-summary-november-10-2024)。代码：[订阅事件](../../voice_gateway/app/freeswitch.py:28)、[终态分类](../../voice_gateway/app/freeswitch.py:590)、[自动重拨](../../backend/app/services/call_service.py:509)。

### P1-05 转人工等待与失败闭环

**现状：部分实现。** 有坐席状态、等待队列、接受/拒绝、失败返回等待、摘要展示；自动选择 ready 坐席，目标主要为 agent:id/default，没有业务技能组路由模型。

**补充：** 按业务/语言/地区路由、工作时间分支、最长等待、等待提示、无人可接时预约/回到 AI/结束。携带已确认字段、转接原因和客户诉求，保护当前上下文。紧急度要真正参与路由；当前 escalate_priority 主要写入原因。

**验收：** 所有坐席离线、坐席点击接受后掉线、转接无人接、客户等待中取消、多个客户同时请求同一坐席；均不能一直无声等待或反复转接。转接成功必须以真实桥接与双向声音验证。已有 PBX 硬截止不等于客户可理解的等待策略。

基线：[腾讯云转接技能组](https://intl.cloud.tencent.com/zh/document/product/1229/81599)。代码：[分配](../../backend/app/services/dispatcher.py:571)、[目标解析](../../backend/app/services/call_service.py:843)、[队列上下文](../../backend/app/api/routers/voice_operations.py:216)。

### P1-06 模型/语音服务故障时的可听见兜底

**现状：已有超时、任务重试、故障日志与媒体关闭保护；缺完整客户交互策略。** AI 失败函数主要记录错误，输出保护的 fallback_reply 不能等同模型调用失败后的播报。

**补充：** 按故障阶段设置最长无响应时间和有限重试。模型慢时播短等待提示；失败时按模式转人工或结束；TTS 不可用时使用预置音频；ASR 失败不继续采集并假装理解。重试中的客户新指令和挂断优先。

**验收：** 分别注入模型超时/429、ASR 断开、TTS 故障、媒体连接中断；客户不会无限沉默，业务动作不重复，运营可看到原因。音频连接已断时不承诺还能播放兜底，以 PBX 终态及后续人工任务收口。

证据：[AI 失败路径](../../backend/app/services/dispatcher.py:325)、[媒体服务错误处理](../../voice_gateway/app/pipecat_pipeline.py:334)。这是结合现有错误路径提出的交付要求，不宣称来自特定厂商 SLA。

## 按业务需要选配

- **DTMF 收号与数字确认**：官方基线有；项目自有路径未发现 DTMF 事件到流程收号的完整处理。需要分机、数字调查等业务时补收号长度、结束符、超时、重输、语音与按键冲突策略。普通营销可后置，承诺提供按键业务时应前置。
- **客户回拨与短信回复**：外呼未接后的客户回拨需要呼入路由、原活动关联和人工/AI 接待；短信“回复 1 联系人工”需要回复接收与工单派发。当前检查未发现完整闭环，不应先在话术里承诺。若采用可回拨号码或提供该短信服务，应成为上线前置条件。
- **更多语言/音色、声音克隆、多智能体转接**：先根据实际客户语言和业务需求选择；配置语言字段不能证明方言效果。普通话单场景替代不必为了功能数量一次性全部补齐。

## 实施依赖与验收顺序

1. 明确本业务的结果枚举、必填字段、停止触达与预约规则，定义可执行动作及证据结构。
2. 优先修复已复现的否定/疑问误判，并实现 P1 的会话策略、特殊接听和异常出口。
3. 让运营可配置这些策略，加入全流程样例、版本绑定和结果交付状态；复用现有管理入口。
4. 在隔离环境验证正确动作、保存回显、重试幂等和过期事件；再做真实电话逐场景验收，之后做单机 200 路、整体 500 路容量和长稳测试。
