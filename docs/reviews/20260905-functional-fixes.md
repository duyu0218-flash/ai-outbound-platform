## 修复对应关系

| 原问题 | 本次行为 | 主要位置 |
| --- | --- | --- |
| P1：转人工迟到响应覆盖终态或接通状态 | 发命令前，通话、交接、坐席在同一事务中绑定。返回时按拨号轮次、交接状态、分配坐席和本次交接时间确认归属，只更新仍属本次的交接，不覆盖通话回调结果。失败响应也不能回滚新的交接。 | `backend/app/services/call_service.py` 的 `transfer_handoff`；`voice_operations.py` 的 accept 入口 |
| P1：手动转人工未接听无法回队 | 手动和队列接受共用交接生命周期，创建/复用 HandoffRequest，保持 transferring 等待网关事件；未接听可释放坐席并重新入队，命令失败可重新接受。 | `call_service.py` 的 `handover_to_human`、`transfer_handoff` |
| P1：任务修改后沿用旧通话配置 | 保存和重启时同步未拨通话的号码、模式、最大尝试次数、流程版本/入口和流水线待选状态；已实际拨出的记录保留历史执行快照。移出的未拨客户撤出待执行队列。 | `campaigns.py` 的 update；`call_service.py` 的 `sync_unattempted_campaign_call` |
| P2：坐席先分页再筛权限漏数据 | 在 SQL 分页之前按坐席筛选；通话列表的上一页、下一页请求服务器对应页码；时间相同按 ID 稳定排序。 | `calls.py`、`call_service.py`、`frontend/src/pages.tsx` |
| P2：任务只能选择首批 200 人 | 支持服务端搜索、继续加载下一页及已选人数；已保存 ID 分批查询标签，切换关键词和编辑时保留选中项。接口新增受租户过滤和 200 项上限约束的 ids 参数。 | `contacts.py`；`frontend/src/campaign-contact-select.tsx` |
| P2：恢复无剩余工作的任务不完成 | 恢复后立即执行统一完成判定；没有活动、排队或重试记录即完成。 | `campaigns.py` 的 resume |
| P2：重试次数不能为 0 | 前后端允许 0；0 对应一次初始拨号，失败/未接听后不安排任务自动重试。 | `schemas.py`、`frontend/src/pages.tsx` |

## 已知问题、环境限制及正式上线前置条件

- 在上述已覆盖场景中，七项问题未再复现；这不是全系统无缺陷声明。
- 通话列表浏览器分页用例拦截了列表响应，用于确认界面真实发送第二页请求；权限与 SQL 分页使用 SQLite/PostgreSQL 测试验证。两层证据分开。
- 浏览器的转接命令使用 MockAdapter，通话事件使用合成 webhook；没有连接运营商或真实客户，没有发送真实短信。浏览器验收不代表真实 SIP/RTP、FreeSWITCH、云 ASR/TTS、录音对象存储或手机端验收。
- 未进行生产数据迁移、真实并发长稳压测、网络故障恢复演练和生产部署。历史卡住的交接/通话记录没有自动补拨、补发或回写，避免影响历史业务。
- 原有本机业务实例仍未替换，不能通过访问旧实例来判断本次代码是否生效。本次无数据库结构变更。
- 正式上线前，需评审并发布本次代码到目标环境，复核真实线路和凭据配置，完成真实语音、转人工、录音/短信、容量和故障恢复验收，并单独确认是否需要修复既有异常历史记录。

初期浏览器尝试受 macOS 沙箱限制，授权运行本机 Chromium 后解除；后续失败来自带图标按钮和下拉框的测试定位，已按实际界面修正。最终上述 10 项全通过，没有通过放宽业务断言掩盖功能失败。

验收清理：本轮临时 PostgreSQL/Redis 容器和浏览器验收服务已停止，原有业务实例未变更。
