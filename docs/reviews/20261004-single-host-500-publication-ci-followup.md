# 发布后 CI 安全修复记录

日期：2026-10-04，北京时间。关联 [PR #48](https://github.com/duyu0218-flash/ai-outbound-platform/pull/48)。

首次发布提交 `291844648b8b3480965a1769b8e62517818bfdb7` 的 GitHub CI #123 有八个 job 成功，包括四服务回归、前端构建/覆盖、PostgreSQL/Redis、浏览器验收和部署配置；供应链审计失败，原因是原有 `PyJWT[crypto]==2.13.0` 被报告存在 13 项已知漏洞。没有忽略漏洞、放宽审计门槛或把该轮 CI 描述为全部通过，完整失败日志与 job 结果保留在证据目录。

后端将唯一 PyJWT 依赖精确升级到 **2.15.1**，保留 crypto extra。该版本通过 PyPI 可用版本及[官方发布](https://github.com/jpadilla/pyjwt/releases/tag/2.15.1)确认；后续实际审计没有报告包括原先未列 fix version 条目在内的已知漏洞。身份验证业务仍固定允许的算法列表，不改认证、AI 调度、模型恢复、回调处理或生产准入代码。补丁先经独立静态审查再测试，最终补充审查见[独立审查报告](20261004-single-host-500-publication-ci-independent-review.md)。

实际验证包括：

- PyJWT 2.15.1 定向 `pip-audit --strict --no-deps --disable-pip` 退出 0，未发现已知漏洞。
- 全新后端环境中，使用既有审计脚本收集全部已安装第三方依赖（包括 dev 和审计工具），仅显式指定可写缓存目录；同等严格审计退出 0，未发现已知漏洞。`--no-deps` 在此针对完整已安装清单，未省略其传递依赖。
- `pip check` 与仓库版本约束检查通过；crypto extra 正常安装，实际环境版本另有记录。
- 独立进程分别用 PyJWT 2.13.0 和 2.15.1 签发/校验相同合成 HS256 令牌，两方向互操作均通过。没有保存真实用户令牌或生产密钥。
- 新增 15 个安全回归案例，验证正常签发、过期、错误签名、不允许的算法、unsigned、异常 exp/nbf/iat 值及有正确签名的深嵌套载荷。拒绝边界返回 401；解析递归错误没有变为 500。
- 全新临时 SQLite 数据库的完整后端回归：**337 passed, 17 skipped**；所有新增案例通过。17 项跳过与 PostgreSQL/Redis 环境有关；新依赖的完整 PostgreSQL/Redis 及其他服务审计由更新后的 PR CI 再执行，结果以 PR checks 为准。

初次完整回归为 336 passed、17 skipped、1 failed，失败来自新增测试把可被当前 Python 解析器接受的 2000 层合法 JSON 当作递归错误。实际探测确认 10000 层触发 RecursionError，仅修正测试深度，业务代码没有更改；在第二个全新数据库中重跑通过。初次测试日志、两个测试摘要和设计修正记录均保留。第一次本地审计因默认缓存位于只读目录失败，显式指定临时缓存后正常审计；该失败日志同样保留。

该历史证据及其 manifest 原字节保留，记录的是测试时快照；不能用其摘要要求后续依赖文件保持旧版本，也不能声称 PyJWT 2.15.1 已运行此前三轮负载。此次额外补丁验证的是依赖安全及认证兼容性，没有再执行 500 路负载。真实语音容量、有效发压及 conversation control SLO 的未通过状态继续保留，本地硬件限制不作为软件交付阻断。
