## 六项逐项结果

| 项目 | 本次实现 | 当前验证边界 |
|---|---|---|
| 1. AI 动作拆分 | 专用 AI worker 的准备、播放结果和业务落库分别使用短事务；HTTP 等待运行在有界 AI 协程内。批量查询模型等待中的通话状态，发送前和回写时仍复核 attempt/turn。准备好的动作保存到已有 Outbox；业务落库、回调 Outbox 与动作完成标记原子提交。 | 12 个播放请求同时等待时 DB 连接占用为零、DB 工作池仍可执行；重试不重新生成模型回答、不重复写决策。50/80/100/125 档性能未重测。 |
| 2. 故障网络隔离 | 模型失败提示、等待提示和失败收尾使用同一分阶段路径，不在 AI DB 池等待远端。播放使用独立于签名 nonce 的稳定命令 ID，网关持久保存意图；确认丢失时只查媒体缓存，未确认则保留未知状态。短信发送意图先落库，未知结果不自动重发。 | 模型失败期间 DB 池可用；等待播放时发生挂断，迟到回包不覆盖终态。取消、任务所有权、故障状态等回归通过；首个播放回执丢失或结果持久化失败均标记未知，恢复只查询，不重复播放。 |
| 3. Inbox 事务 | 计时覆盖分区锁、选择、通话锁、业务 SQL、记账、最终提交和总时间。预算从前置操作开始；根据实际事务耗时收缩下一批锁定数量。保留 FIFO、锁顺序和批末原子性；健康文件保存有界阶段统计。 | SQLite 收取、重放、回滚、顺序及静态配置测试通过。真实 PostgreSQL 锁/WAL/checkpoint、600 events/s 和 1200 events/s 均未重测。 |
| 4. 共享语音许可 | 唯一网关账本按 provider/account/region/product 记 ASR 逻辑预留、实际连接及 TTS 请求。ASR 重连重叠另占额度，未知释放不按 TTL 回收；TTS 共享并发及滚动一分钟请求额度。媒体进程在实际服务边界申请，禁用 SDK 隐式 TTS 重试，复用媒体 RPC 连接池。提供受独立安全管理员保护的状态与人工对账入口。 | 竞争申请不超配额、跨账本实例仍保留未知占用、重连、TTS 窗口、错误 owner、停用/换账号不得遗忘存量均通过本地测试。供应商真实批准额度与释放语义未验证。 |
| 5. 录音源盘 | PBX 挂断完成后写源文件完成凭据；上传方回读对象并核对全部字节的 SHA-256/大小，再以独立清理凭证要求源节点回收。源节点复验文件、完成标记和保留期，删除前持久化凭据。源盘低水位/不可读时停止新拨号。 | 未完成、摘要错误、修改后文件、符号链接、保留期未到均不删除；清理 ACK 丢失后无需重新下载已删除源文件；远端损坏时保留源文件。磁盘不足明确返回未受理，已受理呼叫的重试仍返回原结果。真实 PBX/S3 与持续上传中断未验证。 |
| 6. 完整验收 | 修正现有对话发压为绝对排程，输出逐 10 秒计划/发出/完成量、排程滞后及每轮截止违约；补全应用/部署文件哈希。新增独立主机 8/24h 工作负载监督器，记录固定镜像、持久检查点、轮转日志，并只清理自己的进程组。 | 工具单测和短时模拟监督通过。监督器完成始终不等于容量通过；需要配置真实工作负载并补采 SIP/RTP/云服务/录音/桥接证据。**实际第六项验收未完成。** |

## 配置、发布与恢复

1. `docker-compose.single-host-500.yml` 已要求控制网关及 12 个媒体进程启用共享语音许可。`VOICE_QUOTA_BUDGETS_JSON` 必须填写真实批准的 ASR/TTS 账号、地域、产品及额度；TTS 还需一分钟请求预算。示例不是已批准额度。500 全 AI 必须另核对重连余量。
2. 新增 `VOICE_RECORDING_CLEANUP_TOKEN` 与 `VOICE_RECORDING_RESERVE_BYTES`。清理 token 必须与下载签名、普通服务、媒体 RPC、安全管理员凭证不同；预检会拒绝复用。适配器源地址 allowlist 需允许配置的节点。源录音卷改为网关可写，实际部署必须核对镜像 UID 的受限目录权限。
3. 源盘 reserve 是必须保留的空闲字节，应覆盖现有通话继续录音、上传中断和余量。例如 500 路 8kHz 双声道 PCM 的两小时原始数据约 115.2GB；还需加临时副本、WAL/日志与余量，不应直接照抄示例阈值。
4. ASR 默认仅依据提供方完成确认释放；普通 websocket 正常关闭能否释放需供应商验证后才允许设置 `VOICE_QUOTA_NORMAL_CLOSE_RELEASES=true`。未知状态保留占用，管理员凭真实提供方关闭证据对账；不得为恢复可用性直接清空账本。
5. 更新必须先停拨并排空 AI、播放后续、媒体和在途命令，备份数据库及唯一网关账本，再同步升级后端/网关/全部媒体/录音适配器。不能混跑新旧动作执行者；回退前同样排空。新增准备动作使用原 Outbox JSON；语音许可/命令表由网关启动时在自身 SQLite 账本初始化，不要求新建后端业务表。
6. `/tmp/ai-worker-health.json` 的 `stage_timings` 与 `/tmp/callback-inbox-health.json` 的 `transaction_timings` 提供最近至多 2048 个样本的阶段统计。它们不是全程容量 P99；完整验收还需逐事件 trace、PG 等待/WAL/checkpoint 与 cgroup 采样。
7. `scripts/run-single-host-soak.py --manifest <文件> --output <新的目录>` 接受显式 argv 数组、目标主机、7 类服务的固定镜像摘要及 `duration_seconds=28800/86400`。它不会自动选号码/线路，也不自动判断容量通过。工作负载通过 `ACCEPTANCE_OUTPUT_DIR` 获取本轮证据目录；需将 SIP/RTP、首音、打断、录音和回调 trace 导出到该目录。短时工具自验可使用 `--smoke`，不能替代长稳。
