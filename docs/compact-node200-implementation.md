# 四节点部署代码优化与验证记录

日期：2026-09-07。目标：四台应用服务器，单节点 200 路、集群开放 500 路；PostgreSQL、Redis、负载均衡与录音对象存储采用托管服务。运营商线路 500 并发按已确认前提处理。自有系统直连通信与云 AI 基础服务，不依赖原第三方外呼平台完成业务交付。

本轮已完成代码、配置模板及隔离环境验证，尚未证明单节点 200 路或集群 500 路真实通话能力。已有 P1/P2 工作区改动保留，未覆盖原数据库和业务容器；未创建提交、未推送、未发布生产。

## 本轮改动

| 改动 | 解决的问题与实际行为 |
|---|---|
| 持久节点归属与准入 | 同一事务取得平台锁、核验全局及节点容量、写入拨号状态和节点地址；拨号中及未知状态继续占名额，不能靠 Redis TTL 自动释放。配置全局 500、每节点最多 200。 |
| 调度与健康检查 | 仅选择身份匹配、探测未过期、线路授权匹配且有容量的节点；按占用比例分配。首节点故障时，其他健康节点可继续接单，API 不再依赖固定首节点判断整个集群就绪。 |
| 通话指令路由 | 播放、打断、挂断、转人工回到通话持久记录的节点，携带拨号轮次和提供方呼叫标识，避免修改默认地址后把已有通话命令发错节点。 |
| 网关事件回传 | 持久 SQLite 队列、复用 HTTP 连接、有限并行、单通话顺序保持；慢请求和重试只阻塞所属通话，磁盘操作移出事件循环。保留单网关进程独占账本。 |
| 后台执行池 | 按空闲槽持续领取任务，PostgreSQL SKIP LOCKED 避免重复领取；AI、业务回调、录音、质检分别限并发。慢任务不会让整批任务停等。 |
| 终态质检与旧结果保护 | compact 配置下，结束状态和待质检任务同事务入库；耗时质检移到后台。新客户终句使旧 AI 结果失效，拨号轮次继续独立校验。 |
| 部署与运维 | 独立 Compose 模板将业务与媒体组件合并到每台主机，不再本机部署数据库/Redis。提供集群状态及逐节点排空脚本，排空同时等待持久通话和待回调清零。 |
| 前端构建修复 | 补齐此前 P1/P2 状态新增项对应英文词条，恢复 TypeScript 构建。 |

当前部署入口见 [deploy/compact/README.md](../deploy/compact/README.md)。每台两个 API 进程、一个任务 worker、一个媒体网关进程；数据库连接上限每台 18、四台 72，另留运维迁移连接。每台 AI 执行槽 64 为起测预算，不等同于已验证模型吞吐。已保存的租户、任务和线路限额继续生效，不自动覆盖。

关键业务回归使用外呼项目链路：登录 → 客户搜索/保存 → 任务创建/编辑/启动 → 模拟通话/转人工 → 结束与事件 → 设置保存 → 退出。通用规则中的门店、购物车、支付、订单链路不是本项目业务入口，不适用。

## 回调队列对比压测

相同本机条件，持久 SQLite 队列，200 个模拟 call_id，400 事件/秒输入 4 秒，共 1,600 个事件；HTTP 接收方为每次等待 5ms 后确认的 MockTransport。输入后最多等待 3 秒。它只测事件发送队列，没有 SIP、RTP、ASR、TTS、LLM 或生产数据库。

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 输入结束时已确认事件 | 236 | 1,597 |
| 最终已确认事件 | 400 | 1,600 |
| 最终队列积压 | 1,200 | 0 |
| 总测量耗时 | 7.011 秒，等待预算耗尽 | 4.020 秒，全部确认 |
| 接收端观测最大并行 | 1 | 5 |

证据：`callback-benchmark.json`、`benchmark_callbacks.py`，优化前快照保存在该目录 `baseline/`。该结果证明此合成场景的串行积压得到缓解，不能外推为 500 路真实电话容量，也没有证明此前规划的 1,000 事件/秒持续目标。

## 未验证项、已知问题与环境限制

- 未在目标 Linux 服务器执行单节点 200 路真实双向音频、集群 500 路、8/24 小时长稳、500 个同步终句、带负载录音与报表压测。16 vCPU/32GB 是起测候选规格。
- 四台主机、托管数据库/Redis、云 LB/对象存储和正式服务凭据尚未在本轮配置上线；容器 CPU 上限不是资源预留保证。
- 跨 PBX 的坐席注册及转人工真实路由仍需配置并联调。可选 SIP 入口只有部署挂载入口，尚未提供可直接上线的 OpenSIPS 配置；不能靠随机负载均衡后继续使用本机分机查找。
- 客户插话与跨网络迟到媒体指令需要全链路压力验证；后端序列/轮次校验不等同于已经验证媒体层在所有并发时序下无旧音频。
- 节点崩溃会中断该节点已有通话，当前方案不提供通话热迁移；持久未知通话要可靠对账后释放。三台剩余节点有设计余量不代表故障瞬间可无损恢复 500 路。
- 未执行真实四节点排空、故障恢复、迁移回滚、生产备份恢复和坐席真机验收。本轮没有调用运营商进行真实外呼。
- 清理后核对原业务容器仍在运行，其中原 `ai-outbound-freeswitch-media` 当前健康标记为 unhealthy，原因本轮未排查；该容器未部署本轮源码，不能用其他容器健康推断当前改造已上线。

本轮两个临时测试数据库/Redis 容器及测试 API、Agent、worker 均已停止清理；测试日志保留。原业务容器及数据卷未停止或删除。
