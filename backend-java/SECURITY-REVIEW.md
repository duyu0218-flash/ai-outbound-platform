## 保留 Python Agent 的额度回归补充

首次 PR CI 的双进程共享额度测试出现 OperationalError，旧测试只记录异常类型，无法回溯其具体阶段。本机原并发用例连续 10 次未复现，但定向 WAL 连续性测试在旧代码上明确失败：初始化连接关闭后、空闲锚点重开前，WAL 文件会消失。已让初始化事务提交后的同一连接直接成为空闲锚点，消除该窗口；不延长原 0.5 秒事务前重试边界，也不重放提交失败后的额度预留。

补充启动失败连接关闭、已提交但结果不确定时保留额度的故障回归；Agent 38/38 及连续 10 轮双进程精确 500 额度通过。进程回归错误会记录 startup/reserve 阶段、消息和 SQLite 错误码，远端结果以最新提交为准。仅修复保留 Python 服务的资源生命周期，没有扩大 Java 语言迁移范围。见 `validation/agent-quota-security.json`。

## 配置兼容、环境限制和上线条件

- 生产 Java 必须提前准备 rediss://、JVM 信任的 CA 与匹配的主机名。旧 redis:// 私网配置也会被拒绝；开发/测试仍可使用明文。本轮未发布任何服务。
- CORS 必须填写明确 origin；跨域客户端使用显式 Authorization/API Key。旧 `*` 配置和跨域 Cookie 凭据用法不再支持。
- 历史含标点/Unicode 的 credential_ref 必须人工核对并改成对应的合法配置引用。没有自动替换业务数据库或密钥。
- 没有做生产渗透、JDK/基础镜像完整漏洞扫描；真实 TLS 端点、反向代理、现场旧库、SIP/RTP/WebRTC、录音对象存储、云模型、短信和账单未验收。隔离夹具和 mock 不等于这些链路可用。
- 500 总在途、长稳/突发、公平性、跨进程接管和崩溃恢复仍未验证。上线前完成真实脱敏库迁移恢复、目标部署及证书验证、真机/真实外呼和渠道对账、容量与恢复验收；停止旧核心和 worker，确认无双重消费，再单独批准生产切换。
